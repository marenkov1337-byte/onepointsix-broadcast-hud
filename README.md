# OnePointSix Broadcast HUD

OnePointSix Broadcast HUD is a Counter-Strike 1.6 HLTV/demo broadcast overlay derived from the `hltv_healthbars` project and substantially extended for OnePointSix broadcasts.

## Version

**1.0.0 — first official stable broadcast release.**

> This project is intended for HLTV/demo broadcast use. It relies on engine offsets specific to the supported Counter-Strike 1.6 build, so using another build may cause the HUD to fail or crash.

# Quick installation / HOWTO

## 1. Required Counter-Strike 1.6 version

The current HUD targets the Steam legacy build used during development:

- **Counter-Strike 1.6 / GoldSrc protocol 48**
- **Steam beta branch: `steam_legacy`**
- CS version: **1.1.2.7/Stdio**
- Engine date: **Aug 3 2020**
- Build: **8684**

The current hooks and offsets are written for this build. Do not assume that the DLL is compatible with the current non-legacy Steam build.

In Steam:

1. Right-click **Counter-Strike** → **Properties**.
2. Open **Betas**.
3. Select the **`steam_legacy`** beta branch.
4. Let Steam finish updating the game.
5. Start CS once and verify that the legacy version works before installing the HUD.

## 2. Back up your CS installation

**Do this before copying the broadcast files.**

At minimum, back up any files you already customized under:

```text
Half-Life/cstrike/resource/
Half-Life/cstrike/*.cfg
```

The release contains replacement/custom broadcast resource files. Keeping a backup makes it easy to restore your normal CS installation.

For a dedicated broadcast setup, using a separate clean CS 1.6 installation is recommended.

## 3. Build the DLL

The source is configured for **32-bit Windows / x86**. CS 1.6 is a 32-bit process, so do not build this project as x64.

Requirements:

- Windows
- CMake 3.20+
- Visual Studio 2022 / MSVC
- Visual Studio **v142** C++ toolset
- Git, including the project submodules

Clone/download the repository including its submodules, then from the project root run:

```bat
cmake -B build -G "Visual Studio 17 2022" -A Win32 -T v142
cmake --build build --config Release
```

The DLL generated by the build is:

```text
build/Release/onepointsix_broadcast.dll
```

If you use the project's GitHub Actions workflow, it performs the same x86 Release build automatically.

## 4. Install the runtime files

Your Half-Life folder should contain this layout:

```text
Half-Life/
├── onepointsix_broadcast/
│   ├── onepointsix_broadcast.dll
│   └── sprites.txt
│
└── cstrike/
    ├── b_720.cfg
    └── resource/
        ├── ClientScheme.res
        └── UI/
            ├── BottomSpectator.res
            ├── ScoreBoard.res
            └── Spectator.res
```

Files supplied by this project:

- `onepointsix_broadcast.dll` — the DLL you just compiled
- `cstrike/sprites.txt` → copy as `Half-Life/onepointsix_broadcast/sprites.txt`
- `cstrike/b_720.cfg` → `Half-Life/cstrike/b_720.cfg`
- `cstrike/resource/ClientScheme.res`
- `cstrike/resource/UI/BottomSpectator.res`
- `cstrike/resource/UI/ScoreBoard.res`
- `cstrike/resource/UI/Spectator.res`

The folder containing the DLL **must be named `onepointsix_broadcast`**, because the DLL uses that directory as its runtime plugin path.

The old `timer.png`, country flags, screenshot and `.cstrike_stream` files are **not required** by version 1.0.0.

## 5. Start CS / HLTV

Start Counter-Strike 1.6 normally on the `steam_legacy` branch and enter the HLTV/demo environment you want to broadcast.

For the supplied 720p layout, a **1280×720** game/broadcast resolution is recommended.

## 6. Inject the DLL

The HUD is loaded by injecting:

```text
onepointsix_broadcast.dll
```

into the running:

```text
hl.exe
```

One injector that can be used for this is **Xenos 2.3.2**.

Typical sequence:

1. Start CS 1.6 first.
2. Start Xenos 2.3.2.
3. Select the running **`hl.exe`** process.
4. Add `onepointsix_broadcast.dll`.
5. Inject the DLL.
6. Return to CS.

Xenos is a third-party application and is not included with this project. Obtain it only from a source you trust.

**Do not use this DLL/injection setup while playing on VAC-secured public servers.** This project is intended for a controlled HLTV/demo broadcast setup.

After successful injection, the CS console should show the OnePointSix Broadcast HUD startup banner.

## 7. Load the broadcast configuration

In the CS console, run:

```text
exec b_720.cfg
```

The configuration enables and positions the OnePointSix HUD, including the top bar, minimap and player cards.

If you always use the same broadcast setup, you can also launch CS with:

```text
+exec b_720.cfg
```

## 8. Start a match

For a normal match:

```text
hltv_match_start "Team A" "Team B"
```

For a BO3:

```text
hltv_match_start "Team A" "Team B" bo3
```

For a BO5:

```text
hltv_match_start "Team A" "Team B" bo5
```

During the match:

```text
hltv_halftime
```

At the end of a map:

```text
hltv_map_winner 1
```

or:

```text
hltv_map_winner 2
```

`1` and `2` refer to the permanent **Team 1 / Team 2 identities**, not whichever side is currently T or CT.

Before the next map:

```text
hltv_next_map
```

If automatic round scoring is incorrect, the manual fallback is:

```text
hltv_set_round_score <T> <CT>
```

## 9. Spectator controls

The supplied `b_720.cfg` binds the minimap/player numbers to the keyboard:

```text
1 2 3 4 5  -> Terrorist players
6 7 8 9 0  -> Counter-Terrorist players
```

`Home` toggles the configured overview spectator modes.

## 10. Troubleshooting

### The DLL does not load

Check that:

- CS is using the **`steam_legacy`** branch/build 8684.
- you compiled **Win32/x86**, not x64;
- you injected into **`hl.exe`**;
- `onepointsix_broadcast.dll` is inside `Half-Life/onepointsix_broadcast/`;
- `sprites.txt` is in that same `onepointsix_broadcast` folder.

### The HUD loads but is positioned incorrectly

The supplied layout targets 1280×720. Run:

```text
exec b_720.cfg
```

again after the DLL is injected.

### Weapon/equipment icons are missing

Verify:

```text
Half-Life/onepointsix_broadcast/sprites.txt
```

The HUD uses this file to resolve the native CS sprite resources.

### The game crashes or the HUD behaves incorrectly on another CS build

Return to the supported `steam_legacy` build. The project contains offsets/hooks specific to build 8684; compatibility with other GoldSrc builds is not guaranteed.

### I need to rebuild the DLL but Windows says it is in use

Close CS/`hl.exe` before replacing or rebuilding the injected DLL. An injected DLL remains loaded/locked while the process is running.

# Main features

- broadcast top bar with team names, scores, timer and BO3/BO5 map-win indicators
- bottom player cards with HP, weapon, K/D, C4/defuse information and round-kill badge
- overview minimap with stable spectator numbering and followed-player highlighting
- directional smooth player markers
- smoke, flash and HE detonation markers
- spectator auto-switch behavior, including a short death delay and killer preference
- native CS kill feed and native TAB scoreboard preserved

# Compatibility

The current offsets and hooks target **Counter-Strike 1.6 protocol 48, Steam `steam_legacy`, 1.1.2.7/Stdio, Aug 3 2020, build 8684**.

Other engine builds may require offset changes.
